## 5.3. Үлесті растау

Әр мүшенің үлесі мыналармен расталады:
- git коммиттер тарихы (`git shortlog -sn`) және GitHub → Insights → Contributors;
- әр мүшенің Pull Request-тері мен оларға жасалған code review;
- GitHub Issues: әр тапсырма нақты мүшеге тағайындалған (assignee);
- 5.1-кестедегі файлдар мен артефактілер;
- қорғауда әр мүше өз бөлігін өзі баяндайды (5.4).

## 5.5. Демо-сценарий (4–5 минут)

1. **Қонақ:** басты бет → күндерді таңдап бос көліктерді іздеу → Kia Rio карточкасы.
2. **Тіркелу** жаңа клиентпен → кіру → Kia Rio-ны ертеңнен 7 тәулікке брондау (10% жеңілдікті көрсету).
3. **Қос брондау:** `client@autorent.kz` ретінде кіріп, сол күндерге брондау → қате хабарлама.
4. **Менеджер** (`manager@autorent.kz`): брондар → Растау → келісімшарт пайда болды → ашу, басып шығару.
5. **IDOR:** клиент ретінде бөтен келісімшарттың URL-ін ашу → 403.
6. **Brute-force:** 5 рет қате құпиясөз → бұғаттау хабарламасы.
7. **Әкімші** (`admin@autorent.kz`): көлікке фото жүктеу (содан кейін `.html` файлын `.jpg` деп атап жүктеу → қабылданбайды); аудит журналы → `ACCESS_DENIED`, `ACCOUNT_LOCKED` жазбалары қызыл түспен → пайдаланушыны бұғаттан шығару.
8. **Тесттер:** IntelliJ-те `mvn test` → 32 жасыл тест.

> Демо алдында `data` қалтасын өшіріп, қосымшаны қайта іске қосыңыз — таза демо-деректер.

## 5.6. Қорғауда қойылуы мүмкін сұрақтар

| Сұрақ | Қысқа жауап |
|-------|-------------|
| Қос брондаудың алдын қалай аласыңдар? | `existsOverlap` JPQL сұранысы + көлік жолына `PESSIMISTIC_WRITE` бұғаттау: параллель сұраныстар кезекпен өңделеді |
| Құпиясөз қалай сақталады? | BCrypt, cost=12, әр хэште кездейсоқ salt. Ашық мәтін еш жерде сақталмайды |
| Неге MD5/SHA-256 емес? | Олар жылдам — GPU секундына миллиардтаған іріктейді. BCrypt әдейі баяу және бейімделгіш |
| CSRF дегеніміз не, қалай қорғалған? | Бөтен сайт пайдаланушы атынан сұраныс жібереді. Әр POST-та жасырын токен бар, Spring Security оны тексереді |
| IDOR қалай тексеріледі? | Объект иесінің email-і ағымдағы пайдаланушымен салыстырылады, сәйкес келмесе 403 + аудит |
| `@PreAuthorize` не үшін, URL ережелері бар ғой? | Defense in depth: URL ережесі қате өзгерсе де, әдіс деңгейіндегі тексеру қалады |
| Неге аудит `REQUIRES_NEW`? | Әйтпесе AccessDeniedException транзакцияны кері қайтарғанда, бұзу әрекеті туралы жазба да жойылады |
| Entity орнына DTO не үшін? | Mass assignment: пайдаланушы формаға `role=ADMIN` қосса да, DTO-да ондай өріс жоқ |
| Thymeleaf XSS-тен қалай қорғайды? | `th:text` HTML арнайы таңбаларын экрандайды; `th:utext` қолданылмайды; қосымша CSP |
